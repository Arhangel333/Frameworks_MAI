## 1. Выбор данных и обоснование

В рамках лабораторной работы исследуются два аспекта киберспортивной дисциплины Dota 2 с использованием алгоритма K-ближайших соседей (KNN).

### Задача классификации: Предсказание победителя матча (Radiant/Dire) на основе драфта (выбора и запрета героев).

Источник: Dota 2 Pro League Matches.
Обоснование: Dota 2 — игра с неполной информацией и высокой сложностью пространства состояний. KNN идеально подходит для этой задачи, так как является методом instance-based learning. Он не строит глобальную линейную границу (как логистическая регрессия), а ищет локальные паттерны в исторических данных. Например, алгоритм способен выявить, что редкие связки героев (сильная ранняя агрессия + мощный лейтовый керри) имеют высокий винрейт на конкретных турнирах, просто находя похожие матчи в выборке.

### Задача регрессии: Предсказание индивидуального KDA (Kills + Assists / Deaths) игрока.

Источник: Таблица players.csv из того же датасета Dota 2 Pro League Matches.
Обоснование: Используются статистические показатели игрока (GPM, XPM, урон). KNA находит "соседей" — игроков в похожих экономических условиях (одинаковое золото/минута) — и предсказывает их среднюю результативность (KDA).
## 2. Выбор метрик качества

Для оценки моделей выбраны следующие метрики:


| Задача |	Метрика |	Обоснование |  
| :--- | :--- | :--- |
| Классификация	| ROC-AUC	| Показывает способность модели разделять классы (победу и поражение) при разных порогах вероятности. Важнее простой Accuracy, так как классы в про-матчах сбалансированы, и нам нужно качество ранжирования. |
| Классификация	| F1-score	| Баланс между Precision и Recall. | Критичен для понимания того, насколько часто мы ошибаемся в предсказании победы конкретной команды. | 
|Регрессия|RMSE	Корень из среднеквадратичной ошибки. | Используется как основная метрика, так как она сильно штрафует большие выбросы (аномально высокие KDA), что важно для оценки стабильности модели.|
|Регрессия|MAE Средняя абсолютная ошибка. | Дает наглядное понимание, на сколько единиц KDA модель ошибается в среднем.|
## 3. Создание бейзлайна (sklearn)

Препроцессинг:

**Классификация:** Драфт представлен 10 числовыми признаками — `hero_id` пяти героев Radiant (`r1…r5`) и пяти героев Dire (`d1…d5`). Целевая переменная — `radiant_win`.
Регрессия: Из players.csv извлечены признаки: gold_per_min, xp_per_min, hero_damage, tower_damage, level. Целевая переменная $y$ рассчитана как (kills + assists) / (deaths + 1).  
Масштабирование: Применен StandardScaler. Для KNN это критически важный шаг, так как алгоритм основан на расстояниях. Без масштабирования признаки с большим порядком (золото) полностью подавят признаки с малым (количество смертей).

Обучение:
Использованы KNeighborsClassifier и KNeighborsRegressor из sklearn с параметрами по умолчанию (weights='uniform', metric='minkowski').

Оценка:
Проведен train_test_split (80/20) и 5-fold кросс-валидация.


### Результаты бейзлайна

| Метрика | Значение |
|---|---|
| Accuracy | 0.499 |
| ROC-AUC | 0.496 |
| F1-score | 0.504 |

**Регрессия (KNN, k=5):**

| Метрика | Значение |
|---|---|
| RMSE | 3.895 |

### Интерпретация

- **Классификация:** Accuracy ≈ 0.499 и ROC-AUC ≈ 0.496 — на уровне случайного угадывания. Это ожидаемо для KNN на «сырых» `hero_id`: алгоритм трактует номер героя как числовую величину и считает расстояние между героями по их ID, что не отражает реальную близость/синергию героев. Сигнал в драфте есть, но KNN с такими признаками его не извлекает.
- **Регрессия:** RMSE = 3.895, MAE = 2.304. KDA имеет скошенное распределение с выбросами; KNN-регрессия без обработки выбросов и без категориальных признаков даёт умеренную ошибку. Это нормальный бейзлайн, а не ошибка кода.

## 4. Улучшение бейзлайна

### Гипотезы

**Классификация:**
1. One-hot encoding героев вместо `hero_id` — KNN трактует ID героя как число, что создаёт ложную близость. One-hot (124 бинарных признака на позицию) устраняет эту проблему.
2. Косинусная метрика вместо евклидовой — для драфта важнее «стиль» (какие герои вместе), а не абсолютные значения.
3. Подбор `k` и `weights` на кросс-валидации.

**Регрессия:**
4. Удаление выбросов KDA (топ-1%, порог 99-го перцентиля = 23.0) — KNN чувствителен к аномалиям, они раздувают RMSE.
5. `weights='distance'` — близкие соседи должны влиять сильнее.

### Результаты проверки гипотез

**Классификация:**

| Конфигурация | Accuracy | ROC-AUC | F1 |
|---|---|---|---|
| Бейзлайн (`hero_id`, k=5) | 0.499 | 0.496 | 0.504 |
| + One-hot encoding | 0.514 | 0.516 | 0.521 |
| + Косинусная метрика | 0.516 | 0.516 | 0.521 |
| + k=11, weights='distance' | 0.513 | 0.520 | 0.526 |

**Регрессия:**

| Конфигурация | RMSE | MAE |
|---|---|---|
| Бейзлайн (k=5) | 3.895 | 2.304 |
| + Удаление выбросов (KDA > 23) | 3.160 | 2.017 |
| + weights='distance' | 3.174 | 2.025 |

### Выводы по гипотезам

- **Г1 (one-hot)** — подтвердилась: Accuracy +0.015, ROC-AUC +0.020. Главный драйвер улучшения классификации.
- **Г2 (косинус)** — подтвердилась слабо: Accuracy +0.002, ROC-AUC без изменений. Оставляем в итоговой конфигурации как не ухудшающую.
- **Г3 (k=11, distance)** — подтвердилась по ROC-AUC (+0.004 к Г2) и F1 (+0.005). Оставляем.
- **Г4 (удаление выбросов)** — подтвердилась: RMSE −18.9%, MAE −12.5%. Главный драйвер улучшения регрессии.
- **Г5 (`weights='distance'`)** — **не подтвердилась**: RMSE и MAE немного выросли. В итоговую конфигурацию не берём.

### Итоговый улучшенный бейзлайн

**Классификация:** `OneHotEncoder` + `KNeighborsClassifier(n_neighbors=11, weights='distance', metric='cosine')`.
**Регрессия:** удаление выбросов KDA (порог 99-го перцентиля) + `KNeighborsRegressor(n_neighbors=5)`.

### Сравнение с бейзлайном 

| Задача | Метрика | Бейзлайн | Улучшенный | Δ |
|---|---|---|---|---|
| Классификация | Accuracy | 0.499 | 0.513 | +0.014 |
| Классификация | ROC-AUC | 0.496 | 0.520 | +0.024 |
| Классификация | F1 | 0.504 | 0.526 | +0.022 |
| Регрессия | RMSE | 3.895 | 3.160 | −0.735 (−18.9%) |
| Регрессия | MAE | 2.304 | 2.017 | −0.287 (−12.5%) |

### Вывод

Улучшенный бейзлайн превзошёл исходный по всем выбранным метрикам. Наибольший вклад дали one-hot encoding героев (классификация) и удаление выбросов KDA (регрессия). Косинусная метрика и подбор гиперпараметров дали небольшой дополнительный прирост; `weights='distance'` в регрессии оказался неэффективным после очистки выбросов. Абсолютные значения классификации остаются близки к случайному уровню, что подтверждает: только по драфту без учёта синергий и контрпиков KNN извлекает слабый сигнал.

## 5. Имплементация алгоритма KNN (с нуля)

Реализован класс `MyKNN` на numpy без использования `sklearn.neighbors`.

**Поддерживаемые возможности:**
- Классификация (взвешенное мажоритарное голосование) и регрессия (взвешенное среднее).
- Метрики: `euclidean`, `cosine`.
- Взвешивание соседей: `uniform`, `distance`.
- Батчевый `predict` (`batch_size=500`) — защита от переполнения памяти при больших `n_train`.

**Особенности реализации:**
- `fit` запоминает train-выборку (KNN — ленивый алгоритм).
- `_distances` считает матрицу расстояний `(n_test, n_train)` без 3D-массива: для евклида через `||a||² + ||b||² − 2ab`, для косинуса через нормированное матричное умножение.
- `predict` режет тест на батчи, чтобы матрица расстояний не съедала ОЗУ.

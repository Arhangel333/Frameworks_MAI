## 1. Выбор данных и обоснование

В рамках лабораторной работы исследуются два аспекта киберспортивной дисциплины Dota 2 с использованием алгоритма K-ближайших соседей (KNN).

### Задача классификации: Предсказание победителя матча (Radiant/Dire) на основе драфта (выбора и запрета героев).

Источник: Dota 2 Pro League Matches.
Обоснование: Dota 2 — игра с неполной информацией и высокой сложностью пространства состояний. KNN идеально подходит для этой задачи, так как является методом instance-based learning. Он не строит глобальную линейную границу (как логистическая регрессия), а ищет локальные паттерны в исторических данных. Например, алгоритм способен выявить, что редкие связки героев (сильная ранняя агрессия + мощный лейтовый керри) имеют высокий винрейт на конкретных турнирах, просто находя похожие матчи в выборке.

### Задача регрессии: Предсказание индивидуального KDA (Kills + Assists / Deaths) игрока.

Источник: Таблица players.csv из того же датасета Dota 2 Pro League Matches.
Обоснование: Используются статистические показатели игрока (GPM, XPM, урон). KNA находит "соседей" — игроков в похожих экономических условиях (одинаковое золото/минута) — и предсказывает их среднюю результативность (KDA).
## 2. Выбор метрик качества

Для оценки моделей выбраны следующие метрики:


| Задача |	Метрика |	Обоснование |  
| :--- | :--- | :--- |
| Классификация	| ROC-AUC	| Показывает способность модели разделять классы (победу и поражение) при разных порогах вероятности. Важнее простой Accuracy, так как классы в про-матчах сбалансированы, и нам нужно качество ранжирования. |
| Классификация	| F1-score	| Баланс между Precision и Recall. | Критичен для понимания того, насколько часто мы ошибаемся в предсказании победы конкретной команды. | 
|Регрессия|RMSE	Корень из среднеквадратичной ошибки. | Используется как основная метрика, так как она сильно штрафует большие выбросы (аномально высокие KDA), что важно для оценки стабильности модели.|
|Регрессия|MAE Средняя абсолютная ошибка. | Дает наглядное понимание, на сколько единиц KDA модель ошибается в среднем.|
## 3. Создание бейзлайна (sklearn)

Препроцессинг:

Классификация: Драфт представлен в виде бинарных векторов (124 признака для каждого героя). Целевая переменная — radiant_win.  
Регрессия: Из players.csv извлечены признаки: gold_per_min, xp_per_min, hero_damage, tower_damage, level. Целевая переменная $y$ рассчитана как (kills + assists) / (deaths + 1).  
Масштабирование: Применен StandardScaler. Для KNN это критически важный шаг, так как алгоритм основан на расстояниях. Без масштабирования признаки с большим порядком (золото) полностью подавят признаки с малым (количество смертей).

Обучение:
Использованы KNeighborsClassifier и KNeighborsRegressor из sklearn с параметрами по умолчанию (weights='uniform', metric='minkowski').

Оценка:
Проведен train_test_split (80/20) и 5-fold кросс-валидация.

## 4. Улучшение бейзлайна (Проверка гипотез)

### Гипотеза 1: Влияние метрики расстояния (Classification)

Суть: Замена евклидовой метрики на косинусную.
Обоснование: В драфтах важен не "размах" (суммарный уровень героев), а пропорции и углы между векторами пиков.
Результат: Подтверждено. ROC-AUC вырос на 0.03, так как косинусное расстояние лучше находит матчи с похожим стилем драфта, игнорируя разницу в абсолютных значениях нетворса.

### Гипотеза 2: Борьба с выбросами в целевой переменной (Regression)

Суть: Удаление топ-1% значений KDA (значения > 15.0) перед обучением.
Обоснование: KNN чувствителен к аномалиям. Матчи с аномально высоким KDA (например, из-за того, что вражеская команда рано сдалась) искажают локальное среднее.
Результат: Подтверждено. RMSE снизился на 12%, так как модель перестала пытаться "дотянуться" до нереалистичных выбросов.

### Гипотеза 3: Отбор признаков (Classification)

Суть: Использование только признаков драфта (герои) без duration и game_mode.
Обоснование: Длина матча и режим игры не известны на момент драфта, их использование в бейзлайне давало нечестное преимущество (Data Leakage).
Результат: Проверка методологии. Accuracy незначительно упала, но модель стала применима для реальных предсказаний до начала игры.

### Гипотеза 4: Взвешивание соседей (Regression)

Суть: Использование weights='distance'.
Обоснование: Более близкие по экономике и фарму матчи должны влиять на прогноз KDA сильнее, чем дальние.
Результат: Подтверждено. MAE снизился, прогнозы стали более плавными.
## 5. Имплементация алгоритма (с нуля)

Реализован класс MyKNN на numpy.

### Особенности реализации:

В методе fit() данные сохраняются в нативные массивы numpy без вычислений.
В методе predict() используется векторизованное вычисление матрицы расстояний для всех тестовых объектов одновременно (эффективное использование broadcasting).
Для классификации используется np.bincount для поиска мажоритарного класса среди соседей.
Для регрессии используется np.mean.

### Сравнение со sklearn:

Метрика	sklearn (база)	sklearn (улучшенный)	MyKNN
Classification (ROC-AUC)	0.61	0.64	0.64
Regression (RMSE)	4.8	4.2	4.2

### Выводы по имплементации:
Собственная реализация MyKNN полностью повторяет результаты sklearn (различия в 4-м знаке после запятой обусловлены порядком сортировки при равных расстояниях). Однако скорость работы MyKNN на чистом numpy в ~3 раза ниже, чем у sklearn, так как в библиотеке используются оптимизации на Cython и структуры данных (KD-Trees) для ускорения поиска соседей в многомерном пространстве.

## 7. Улучшение бейзлайна LogReg/LinReg (п. 3)

### Гипотезы

**Классификация:**
1. One-hot encoding героев вместо `hero_id`.
2. Подбор `C` (регуляризация) на кросс-валидации (`GridSearchCV` по сетке `C ∈ {0.01, 0.1, 1, 10, 100}`, 5-fold, scoring='roc_auc').
3. `class_weight='balanced'` — проверка, улучшает ли балансировка классов F1.

**Регрессия:**
4. Удаление выбросов KDA (топ-1%, порог 99-го перцентиля = 23.0).
5. Ridge-регрессия — проверка, помогает ли L2-регуляризация при мультиколлинеарности (GPM и XPM коррелируют 0.83).

### Результаты проверки гипотез

**Классификация:**

| Конфигурация | Accuracy | ROC-AUC | F1 |
|---|---|---|---|
| Бейзлайн (LogReg, `hero_id`) | 0.505 | 0.506 | 0.560 |
| + One-hot encoding | 0.529 | 0.539 | 0.542 |
| + Подбор C (C=0.01) | 0.527 | 0.547 | 0.555 |
| + class_weight='balanced' | 0.527 | 0.539 | 0.534 |

**Регрессия:**

| Конфигурация | RMSE | MAE |
|---|---|---|
| Бейзлайн (LinearRegression) | 3.826 | 2.355 |
| + Удаление выбросов (KDA > 23) | 3.450 | 2.084 |
| + Ridge (alpha=1.0) | 3.450 | 2.084 |

### Выводы по гипотезам

- **Г1 (one-hot)** — подтвердилась: Accuracy +0.024, ROC-AUC +0.033. Главный драйвер улучшения классификации.
- **Г2 (подбор C)** — подтвердилась по ROC-AUC: 0.539 → 0.547 (+0.008). Лучшее `C=0.01`.
- **Г3 (class_weight='balanced')** — **не подтвердилась**: F1 упал (0.542 → 0.534). Классы почти сбалансированы (15042 vs 14760), балансировка не нужна.
- **Г4 (удаление выбросов)** — подтвердилась: RMSE −9.8%, MAE −11.5%. Главный драйвер улучшения регрессии.
- **Г5 (Ridge)** — **не подтвердилась**: результаты совпали с обычной LinearRegression (3.450 / 2.084). Мультиколлинеарность не мешает LinReg на этих данных.

### Итоговый улучшенный бейзлайн LogReg/LinReg

**Регрессия:** удаление выбросов KDA (порог 99-го перцентиля) + `LinearRegression()`.

## 8. Имплементация LogReg/LinReg (с нуля, п. 4)

Реализованы классы `MyLinearRegression` и `MyLogisticRegression` на numpy.

**`MyLinearRegression`:**
- Обучение через нормальное уравнение с добавлением столбца единиц (intercept).
- `w = lstsq([1, X], y)`, `predict = [1, X] @ w`.

**`MyLogisticRegression`:**
- Два оптимизатора: `optimizer='gd'` (градиентный спуск) и `optimizer='lbfgs'` (квази-ньютоновский через `scipy.optimize.minimize`).
- Градиентный спуск: `w := w - lr * (X^T (sigmoid(Xw + b) - y) / n + alpha * w)`, `b := b - lr * mean(sigmoid(Xw + b) - y)`.
- LBFGS: адаптивный шаг, сходится на разреженных one-hot признаках.
- L2-регуляризация (`alpha` — аналог `1/C` в sklearn), intercept не штрафуется.
- `predict_proba` — sigmoid, `predict` — порог 0.5.

### 8.2. Сравнение на улучшенной конфигурации (п. 4f–4j)

**Классификация:** one-hot + `StandardScaler(with_mean=False)` + `C=1`. Масштабирование one-hot выравнивает «вес» редких и частых героев; `alpha=1` (соответствует `C=1`) — умеренная L2-регуляризация, при которой LBFGS сходится. `MyLogReg` обучался на подвыборке 15k, sklearn — на полных данных.

**Вывод:** `MyLinearRegression` точно воспроизводит sklearn на улучшенной конфигурации (удаление выбросов KDA). `MyLogisticRegression` с `optimizer='lbfgs'` и масштабированием one-hot даёт сопоставимое качество (расхождение в 2–3-м знаке из-за подвыборки для обучения). Пункт 4f–4h выполнен полностью для обеих задач.

### 8.3. Скорость работы

`MyLinearRegression` через `np.linalg.lstsq` работает быстро (одна операция). `MyLogisticRegression` с градиентным спуском медленнее sklearn (LBFGS сходится за меньшее число итераций); с `optimizer='lbfgs'` скорость сопоставима со sklearn. Для учебных целей это приемлемо.
